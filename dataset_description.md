# Dataset Description

## Overview

This synthetic dataset represents scheduled home-health clinician visits for a regional care provider. Each row is one scheduled visit with operational context known before dispatch, such as appointment timing, clinician workload, patient geography, weather, traffic, required service type, and prior reliability signals.

The prediction target is `delay_minutes`, the number of minutes the clinician arrives after the scheduled appointment time. Values are nonnegative and right-skewed: many visits are on time or only slightly late, while a smaller number have large delays due to travel, workload, weather, staffing, or difficult service routes.

The data is generated by `raw/generate_raw.py` using a fixed random seed. It does not use real patient, clinician, or location data.

## File Structure

- `raw/data.csv` - labeled source data generated by the deterministic synthetic data script

After running `prepare.py`, the platform should produce:

- `public/train.csv` - labeled training rows
- `public/test.csv` - unlabeled test rows
- `public/sample_submission.csv` - expected submission format
- `private/answers.csv` - private test labels for grading

## Features

| Column | Type | Description |
|---|---:|---|
| visit_id | string | Unique visit identifier. |
| scheduled_date | string | Scheduled visit date in ISO format. |
| scheduled_time | string | Scheduled local appointment time in HH:MM format. |
| weekday | int | Day of week, Monday=0 through Sunday=6. |
| region | string | Synthetic service region. |
| service_type | string | Visit category such as wound care, infusion, assessment, or therapy. |
| clinician_type | string | Clinician credential assigned to the visit. |
| patient_acuity | int | Synthetic patient acuity level from 1 to 5. |
| miles_from_branch | float | Approximate route distance from the branch to the patient. |
| prior_visit_count | int | Number of prior visits for the patient in the recent history window. |
| prior_late_rate | float | Patient-level historical late-arrival rate available before scheduling. Some values are missing for new patients. |
| clinician_daily_load | int | Number of visits already assigned to the clinician that day. |
| previous_visit_gap_minutes | float | Planned gap after the clinician's prior visit. Missing when this is the first visit of the day. |
| avg_route_speed_mph | float | Historical average route speed for the area and time period. |
| traffic_index | float | Forecast traffic burden on a 0-100 scale. |
| precipitation_mm | float | Forecast precipitation for the appointment window. |
| temperature_f | float | Forecast temperature for the appointment window. |
| is_holiday_week | int | Whether the visit falls in a holiday-affected week. |
| authorization_required | int | Whether the visit requires a same-day authorization check. |
| supply_complexity | int | Supply-preparation complexity from 0 to 3. |
| zip_cluster | string | Synthetic geographic cluster. |
| route_zone | string | Synthetic branch routing zone. |
| notes_topic | string | Pipe-delimited scheduling note topics known before dispatch. |
| delay_minutes | float | Target variable: minutes late. Present only in `raw/data.csv` and `public/train.csv`. |
| actual_arrival_time | string | Leakage column present only in raw data; removed by `prepare.py`. |
| dispatcher_adjustment_minutes | float | Leakage column present only in raw data; removed by `prepare.py`. |
| same_day_complaint_flag | int | Leakage column present only in raw data; removed by `prepare.py`. |

## Notes

The raw file deliberately includes a few post-outcome leakage columns so the prepare script can demonstrate that only pre-dispatch information is exposed to solvers. The public train and test files exclude `actual_arrival_time`, `dispatcher_adjustment_minutes`, and `same_day_complaint_flag`.

Several fields require careful handling:

- `prior_late_rate` and `previous_visit_gap_minutes` contain meaningful missing values.
- `scheduled_time`, `weekday`, and `scheduled_date` contain cyclic and seasonal information.
- `notes_topic` is pipe-delimited and may contain multiple scheduling issues.
- `delay_minutes` is nonnegative and right-skewed, making a log-transformed target useful.
